
# Задача для Codex

**Проект:** `api_calc_fork`
**Цель:** Внести минимальные изменения в текущий Python-проект и заменить внутреннюю логику расчёта на упрощённую, **без изменения формата API**.

## 1. Общие требования

Нужно доработать текущий проект по следующим правилам:

1. **Не менять формат request и response**.
2. **Не менять существующие endpoint'ы**, если это не требуется технически.
3. **Не делать валидации бизнес-правил**.
4. **Не реализовывать FoxPro parity**.
5. **Не развивать движок правил** — это будет потом.
6. Реализовать только:

   * извлечение входных параметров;
   * загрузку нового CSV `d_fe1r10p1`;
   * упрощённый расчёт;
   * возврат результата в текущем формате ответа.
7. Изменения должны быть **минимально инвазивными**.
8. Старую FoxPro-ориентированную логику не удалять агрессивно, если это не мешает. Лучше оставить как legacy.

---

## 2. Функциональная цель текущего этапа

Сервис должен:

1. принять текущий входной payload;
2. извлечь данные лица и эпизодов;
3. по статье/пункту найти санкцию в новом CSV `d_fe1r10p1`;
4. выполнить **упрощённый расчёт**;
5. вернуть текущий response format без его изменения.

---

## 3. Что считать упрощённой логикой

На текущем этапе нужно реализовать только следующий расчёт:

### 3.1. По каждому эпизоду

* определить статью;
* определить пункт, если есть;
* найти запись в `d_fe1r10p1`;
* получить:

  * тяжесть;
  * коэффициент тяжести;
  * признак преступление/проступок;
  * допустимые основные наказания;
  * обязательные дополнительные наказания;
  * необязательные дополнительные наказания;
  * минимумы/максимумы по основным наказаниям;
  * минимумы/максимумы по дополнительным наказаниям.

### 3.2. По карточке в целом

* выбрать наиболее тяжкую статью;
* выбрать наиболее тяжкое наказание;
* собрать итоговый упрощённый расчёт.

### 3.3. Что не делать

Не реализовывать:

* проверки обязательности реквизитов;
* словарные проверки;
* предупреждения;
* проверки гражданства/возраста/беременности/детей;
* рецидив;
* условность;
* вид УИС;
* совокупность преступлений;
* возврат "первой ошибки";
* сложную FoxPro-агрегацию;
* все edge cases.

---

## 4. Ограничения

1. **API-контракт не менять**.
2. **Pydantic response model не ломать**.
3. Не переименовывать публичные endpoint'ы.
4. Не делать лишних рефакторингов по всему проекту.
5. Не удалять старые модули, если они не мешают.
6. Новую логику делать отдельным чистым слоем, а не вписывать в старый FoxPro engine.

## Шаг 7. Реализовать новый упрощённый расчётчик

### Новый файл

* `app/domain/services/simple_calculator.py`

### Что сделать

Создать новый класс, например:

```python
class SimplePunishmentCalculator:
    def calculate(self, context: CalculationContext) -> CalculationResult:
        ...
```

### Внутри реализовать

#### 7.1. Расчёт по эпизоду

Для каждого эпизода:

* получить санкцию;
* определить список допустимых основных наказаний;
* определить список обязательных дополнительных наказаний;
* определить список необязательных дополнительных наказаний;
* построить упрощённую структуру диапазонов наказаний.

#### 7.2. Агрегация

* выбрать наиболее тяжкую статью по `koef_hard`, затем `hard`;
* выбрать наиболее тяжкое наказание по заданному приоритету.

### Приоритет тяжести наказаний

Использовать простой фиксированный порядок:

1. `02` — смертная казнь
2. `03` — пожизненное лишение свободы
3. `01` — лишение свободы
4. `11` — ограничение свободы
5. `12` — арест
6. `09` — общественные работы
7. `06` — исправительные работы
8. `05` — штраф
9. иные — ниже

Если код наказания отсутствует, считать менее тяжким.

#### 7.3. Итог

Вернуть:

* рассчитанные данные по эпизодам;
* итоговую статью;
* итоговое наказание;
* агрегированные дополнительные наказания.
